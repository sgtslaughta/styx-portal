# Styx on Kubernetes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the Styx server in the home k3s cluster behind the existing cluster Traefik + cloudflared, and stream the EliteMini workstation through its agent.

**Architecture:** With `ROUTE_BACKEND=k8s`, the backend keeps `build_routes_config()` as the single route source. It translates that dict into Traefik CRDs + Services/EndpointSlices and server-side-applies them into the `styx` namespace over the k8s REST API (httpx, ServiceAccount token), pruning anything stale. Kustomize manifests in `deploy/k8s/` hold the workloads, RBAC, NetworkPolicy and PVC. Cloudflared trust comes from live cloudflared pod IPs, not a CIDR.

**Tech Stack:** Python 3.12, FastAPI, httpx (already a dep, no new deps), pytest, Traefik v3.6 CRDs (`traefik.io/v1alpha1`), Kustomize via `kubectl apply -k`, k3s 1.34 + Cilium.

**Spec:** `docs/superpowers/specs/2026-10-19-k8s-deploy-design.md`

## Global Constraints

- Compose deploy must keep working unchanged: every new setting defaults to current compose behaviour (`ROUTE_BACKEND=file`).
- No new Python dependencies. k8s calls use `httpx`.
- Backend RBAC is limited to namespace `styx`, plus one read-only Role (`pods` get/list) in namespace `cloudflared`. Nothing cluster-scoped.
- No secrets committed. `deploy/k8s/secrets.example.env` holds blank values only.
- All k8s objects the backend writes carry the label `app.kubernetes.io/managed-by: styx-backend`. Prune touches only objects with that label.
- k8s object names are DNS-1123 (lowercase alnum + `-`, ≤63 chars).
- Public entrypoint `websecure`. Cloudflared reaches Traefik at `https://traefik.traefik.svc.cluster.local:443`.
- In k8s mode, skip LAN routers, LAN TLS and proxied-service routes (MVP non-goals).
- Semantic commits (`feat:`, `fix:`, `docs:`, `ci:`). Gates before every commit: `cd backend && .venv/bin/python -m pytest -q` and `.venv/bin/python -m ruff check app/ tests/`. Frontend tasks also run `npm run build`.
- Files under 500 lines.
- Never modify shared cluster components (cluster Traefik, cloudflared deploy, Cilium). Deploy steps against the cluster (Tasks 1, 9) need the owner's go first.

## Review Focus

1. **Forged `CF-Connecting-IP` from LAN/another pod**: must be ignored. Task 5 tests that a non-cloudflared XFF peer with a CF header resolves to the XFF peer; Task 9 proves it live.
2. **k8s API down or 403 during route refresh**: the portal must stay up and log the error, never crash-loop. `strict=True` re-raises (same contract as the file writer). Tested in Task 4.
3. **Workstation goes offline → route removed**: prune must delete its IngressRoute/Middlewares/Service/EndpointSlice. Tested in Task 4.
4. **Workstation `lan_ip` IPv6 or ID longer than 63 chars once prefixed**: correct EndpointSlice `addressType` and a valid truncated name. Tested in Task 3.
5. **Docker absent with stale "running" instances in the migrated DB**: workstation offline-marking and route refresh must still run each monitor pass. Tested in Task 6.

### Task 3: Route dict → k8s objects (pure translation)

**Files:**
- Create: `backend/app/services/k8s_routes.py`
- Test: `backend/tests/test_k8s_routes.py`

**Interfaces — Produces:**
- `MANAGED_LABEL = {"app.kubernetes.io/managed-by": "styx-backend"}`
- `k8s_name(s: str) -> str`: lowercase, invalid chars → `-`, strip leading/trailing `-`. If >63 chars: first 54 + `-` + first 8 hex of sha1(s).
- `to_k8s_objects(config: dict, namespace: str) -> list[dict]`: full manifests (apiVersion, kind, metadata{name, namespace, labels=MANAGED_LABEL}, spec).

Mapping rules (decided):
- Each `config["http"]["routers"][name]` becomes an `IngressRoute` `k8s_name(name)` with `entryPoints: ["websecure"]` (ignore the dict's entryPoints/tls) and one route `{kind: Rule, match: rule, priority, middlewares: [{name: k8s_name(m)}], services: [svc_ref]}`.
- Each `config["http"]["services"][name]["loadBalancer"]["servers"][0]["url"]` gets parsed. If the host is an **IP literal**, emit a selector-less `Service` `k8s_name(name)` (port `{name: "http", port, targetPort: port}`) plus an `EndpointSlice` `k8s_name(name)+"-ep"` (label `kubernetes.io/service-name`, `addressType` IPv4/IPv6, one endpoint, ports `[{name: "http", port}]`). The svc_ref is `{name, port}`. Otherwise reference the existing in-namespace Service: `api` → `{name: "backend", port: 8000}`, other hostnames → `{name: host, port}`. Add `scheme: "https"` when the URL scheme is https. Add `serversTransport: k8s_name(t)` when the service names one.
- Each middleware becomes a `Middleware` `k8s_name(name)` whose spec is the dict body copied as is. Exception: `errors.service` (a dynamic-config service name) becomes the same svc_ref as above.
- `serversTransports[name]` becomes a `ServersTransport` `k8s_name(name)` (spec copied as is).
